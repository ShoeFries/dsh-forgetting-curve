# dsh-forgetting-curve · 遗忘曲线

> 它不管「记什么」，只管「该忘什么」。

一个给 **DeepSeek Harness** 用的记忆预算插件。它盯着你的 `AGENTS.md` / `AGENTS.local.md` 用了多少字节、哪一块超了、哪些条目该压掉，然后把报告和**候选清单**摆在你面前 —— **由你决定**删哪条、折哪条。

它**不会**替你往记忆里写东西，也**不会**在你不点确认的时候改一个字。

---

## 它解决什么问题

用 DSH 的人大多会遇到同一件事：`AGENTS.md` 越写越长，某天突然发现它**整份不生效了** —— 不是截断，是**被整个丢出去**，会话里只留一句 `omitted AGENTS.md`。

因为这份文件跟 `AGENTS.local.md` 挤同一个预算（默认 **65,536 字节**），超了就是一票否决。

这个插件做的事：

1. **量** —— 按 `[B1]`..`[B9]` 块标算出每块用了多少、离额度差多少（每块带 ±10% 的正常波动区，超出才标红）
2. **判** —— 每条句子过一遍判据，分成「永远不动 / 可以压成一句 / 可以忘」
3. **列** —— 把能删的、能压的**逐条列出来**，带完整原文和行号
4. **等你点头** —— 你勾完、写一句摘要、点确认，它才动手；动手前**先整份备份**

## 安装

```bash
# 在你的 DSH profile 目录下
pnpm add dsh-forgetting-curve
```

或者手动：

1. 把本仓库放进 profile 的 `node_modules/`（或用 `link:` 指向本地目录）
2. 在 profile 的 `package.json` 的 `dsh.profile.bundles` 里加上 `"dsh-forgetting-curve"`
3. 重启 DSH

装好后在 **设置 → 遗忘曲线** 里能看到面板。

> **注意**：这个插件声明了 `inject: ['webServer']`。少了这一句，DSH 重启时插件会比 webServer 服务先启动，导致面板一直显示「读不到宿主」（404/405）。如果你是 fork 后自己改的，别把这行删了。

## 配置

配置文件在 `~/.dsh/dsh-forgetting-curve.json`（首次运行后生成）：

```json
{
  "workspace": "",
  "periodDays": 30,
  "mode": "proposal",
  "backup": true,
  "autoOnAlert": true,
  "reportDir": ""
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `workspace` | `""` | 工作区路径。**留空 = 用进程当前目录** |
| `periodDays` | `30` | 多久体检一次（天） |
| `mode` | `proposal` | `proposal` = 只出提案；`auto` = 到点自动跑（**仍然只备份 + 出报告，不改 `AGENTS.md`**） |
| `backup` | `true` | 动手前整份备份 |
| `autoOnAlert` | `true` | 注入块踩到 85% 立刻跑一次 |
| `reportDir` | `""` | 月报目录，留空 = `<工作区>/_handover/_记忆备份/_报告` |

也可以在**设置页**里改（设置页优先于文件）。

## 用法

打开 **设置 → 遗忘曲线**，面板上有：

- **顶部**：总量 / 预算 / 百分比 / 距红线还有多少
- **表格**：每块的用量、额度、差额、判层分布、可折/可删条数
  - 差额落在 ±10% 内显示「波动 +154」；超出才红
- **重新扫描**：当场重算（绕过缓存）
- **出报告**：写一份 markdown 报告
- **备份**：手动整份备份
- **切到自动模式 / 切回只读**：改运行模式
- **看折叠候选 / 看删除候选**：列出候选（完整原文 + 行号）
- **恢复最近备份**：误删的退路

### 删除

勾选 → 点「确认删掉这 N 条」→ 它先备份、再删、写完一份 `改动记录-<日期>.md`（记了改了哪几条、备份在哪、怎么恢复）。

### 折叠

**折叠必须由你写那一句。**

勾上一条后，那条下面会弹出一个输入框：「这条留成什么？」—— 你写一句，折叠后文件里就是这句。不写不让确认。

> 为什么不自动生成：机器给「可以压」的条目生成的摘要，对**缺少来由**的条目只会产出一句占位提示。落进文件就等于把原文换成废话。所以这条路径**强制人工**。

## 恢复

三条路，随便哪条：

1. 面板上点 **「恢复最近备份」**
2. 命令行 `node index.js --restore 2026-11-08`（省略日期或写 `latest` = 最近一份）
3. 直接去 `<工作区>/_handover/_记忆备份/<日期>/` 把文件复制回来

备份是**整份**的（`AGENTS.md` + `AGENTS.local.md` + `manifest.json`），每次动手前都会刷新。

## 判据（它是怎么分的）

**纵轴是组块，横轴是块内位置，颜色才是属性。**

```
纵轴  B1–B9         结构：丢一格只丢一格
横轴  块内第几条      结构：能不能单独替换
颜色  三级/二级/一级   属性：能不能动
```

| 层 | 长什么样 | 怎么处理 |
|---|---|---|
| **三级** | 身份、硬约束、「一律/不许/只能」的规矩、已经定下来的事 | **永不动** |
| **二级** | 有明确事实、但换台机器/换个时间也查得到（版本号、路径、URL、命令） | **压成「一句来由 + 一个指针」** |
| **一级** | 过程、当时的情绪、已经过去的一次性事件 | **可以忘** |

**块标约定**：`AGENTS.md` 里的标题带 `[B1]`..`[B9]` 就归到对应块；不带块标的内容归 `B0`（会在报告里提示）。`AGENTS.local.md` 不拆块，独立算额度。

**块名和额度**在 `lib/blocks.js` 的 `BLOCKS` 里，想改自己的分类就改那里。

## 理论支撑（以及它没有照搬哪一条）

### 1. 硬约束：注入预算是一票否决，不是截断

DSH 把 `AGENTS.md` + `AGENTS.local.md` 塞进同一个预算（`dsh-base` 的 `cordis.patch.yml` 里 `maxBytes`，默认 65536）。**超了不是切掉尾巴，是整份被丢出去** —— 会话里只剩一行 `omitted AGENTS.md`。

所以这个插件的第一性原理不是"记忆越少越好"，而是：**总量必须永远低于这条线**。它把这件事做成了可见的数（总量 / 百分比 / 距红线）和可操作的清单。

### 2. 为什么不按"时间"衰减 —— 它借用的是艾宾浩斯的**名字**，不是他的模型

Ebbinghaus（1885）测的是**无意义音节**的遗忘速率，得到那条著名的时间曲线。但真实记忆文件的内容不是音节：

- **身份和硬约束**放三个月也不会"淡"，删掉它反而立刻出事
- **某台机器的端口号**当时记得再牢，换台机器就没用了，跟时间无关
- **一次性的过程**（当时怎么修的）价值随时间衰减，但衰减原因是"它已经完成了"，不是"过了 30 天"

**所以这个插件的判据是「结构 + 可替代性」，不是「年龄」。** 它借用"遗忘曲线"这个名字，是因为两件事在做同一个动作：**决定什么留下、什么放下**。

### 3. 组块化（chunking）：纵轴为什么是块，不是条目

Miller（1956）的 7±2、Cowan（2001）的 4±1 说的是同一个现象：**人的工作记忆按"块"计数，不按"信息量"计数。**

放到记忆文件上有个直接推论：**一块整体坏掉，比一堆条目各烂一点更难恢复。** 所以：

- 纵轴切成 `B1..B9` —— **丢一格只丢一格**，别的块不受牵连
- 横轴看块内位置 —— **这一条能不能单独替换**（列表项能，段落中间那句不能）
- 颜色（三级/二级/一级）才是**属性** —— 能不能动

把"结构"和"属性"分开，是这个插件和普通"按字数裁剪"最大的区别：普通裁剪会让文件**词还在、事没了**；分层之后，**该留的整块留下，该走的一整条走**。

### 4. 为什么"折叠"必须人写摘要

压缩的失败模式不是"压得太狠"，是**压掉了前因**。

一条记忆之所以有用，往往不在结论（"隐藏文件写不进去"），而在**为什么记它**（"那天写坏过一次，排查了半天"）。自动摘要只会保留前者，于是文件看起来还很满，**下次遇到同样的事却完全想不起当初的教训**。

所以这个插件把这一步交回给人：**摘要你自己写一句。** 机器只负责把候选、原文、行号摆好，以及保证删错了能找回来。

## 安全边界

- **只改 `AGENTS.md`**。`AGENTS.local.md`（自动层）一律拒绝。`_handover/`、`_memory/` 一根手指都不碰
- **先备份，备份失败就绝不动手**
- **只接受白名单操作**（`scan` / `report` / `backup` / `setMode` / `items` / `apply` / `restore`），请求体里带 `path` / `file` / `content` 这类键一律 **400** —— 没有任何参数能指定「写哪个文件」
- **拒绝跨站请求**（校验 `Origin` 与 `Host` 一致）
- `AGENTS.md` 通常是隐藏文件，写入前会自动 `attrib -h`、写完挂回（否则 Node 会 `EPERM`）

---

## 已知限制

- **折叠的摘要必须人写**（见上）
- **面板上的改动要重开一次设置才生效**（客户端 bundle 是增量热更）
- **重启 DSH 后靠 `inject` 等 `webServer` 就绪**，如果还是 404，重载一次插件即可
- 不做「定时自动改文件」—— `auto` 模式也只备份 + 出报告
